# CSAPP 1장 요약정리

## 1. 프로그램 실행의 출발점: 번역 체인

C 프로그램(`hello.c`)은 바로 CPU가 실행할 수 없다.  
다음 4단계를 거쳐 실행 파일이 된다.

1. 전처리(`cpp`): `#include`, `#define` 처리
2. 컴파일: C 코드 -> 어셈블리 코드
3. 어셈블: 어셈블리 코드 -> 목적 파일(기계어)
4. 링크: 여러 목적 파일/라이브러리를 결합해 실행 파일 생성

핵심: "코드를 작성하는 일"은 곧 "번역 파이프라인을 이해하는 일"이다.

---

## 2. 왜 컴파일 시스템 이해가 중요한가

### 성능
- `switch` vs `if-else`, `for` vs `while`처럼 문법 형태만으로 성능을 단정할 수 없다.
- 함수 호출 오버헤드, 메모리 접근 방식(포인터/배열), 수식 재배치가 실제 성능에 영향을 준다.

### 링크/빌드 디버깅
- "심볼을 못 찾는다"는 에러의 의미를 알아야 빌드 에러를 해결할 수 있다.
- 전역/정적 변수, 정적/동적 라이브러리, 링크 순서가 결과를 바꾼다.

### 보안
- 버퍼 오버플로우는 입력 검증 부족에서 시작되는 대표 취약점이다.
- 스택에 데이터/제어 정보가 저장되는 구조를 이해해야 안전한 코드를 작성할 수 있다.

---

## 3. 시스템 하드웨어의 큰 그림

- **버스**: CPU, 메모리, I/O 사이 데이터 통로
- **입출력 장치**: 키보드, 디스크, 네트워크 등
- **메인 메모리**: 실행 중 코드/데이터 저장
- **프로세서(CPU)**: 명령어 인출/해석/실행
  - PC(Program Counter): 다음 명령어 주소
  - ALU: 산술/논리 연산

CPU 기본 동작:
- Load(메모리 -> 레지스터)
- Store(레지스터 -> 메모리)
- Operate(ALU 연산)
- Jump(PC 갱신)

---

## 4. 캐시와 메모리 계층

- 큰 저장장치는 일반적으로 느리고, 빠른 저장장치는 비싸다.
- 그래서 L1/L2/L3 캐시를 두어 CPU와 메모리 속도 차이를 줄인다.
- 메모리 계층의 핵심은 "상위 레벨이 하위 레벨의 캐시 역할"을 한다는 점이다.

핵심 문장: 성능 문제는 알고리즘뿐 아니라 **메모리 접근 패턴**에서 자주 결정된다.

---

## 5. 운영체제가 제공하는 추상화

### 프로세스
- 실행 중인 프로그램에 대한 OS 추상화
- 컨텍스트(PC, 레지스터, 메모리 상태)를 가진다.
- 컨텍스트 스위칭으로 여러 프로세스를 교차 실행한다.

### 스레드
- 프로세스 내부의 실행 단위
- 코드/전역 데이터 공유, 실행 흐름은 분리

### 가상 메모리
- 각 프로세스가 메모리를 독점 사용하는 것처럼 보이게 함
- 코드/데이터, 힙, 스택, 공유 라이브러리, 커널 영역을 논리적으로 분리

### 파일
- 입출력 장치를 통일된 인터페이스로 다루게 해주는 추상화

## 6. 네트워크 관점

- 시스템은 네트워크를 통해 다른 시스템과 상호작용한다.
- 즉, "한 대의 컴퓨터"가 아니라 "연결된 시스템" 관점으로 사고해야 한다.

---

## 7. 1장의 핵심 법칙: Amdahl의 법칙

- `T(new) = (1-a)T(old) + (aT(old))/k`
- 가속비: `Speedup = 1 / ((1-a) + a/k)`

의미:
- 전체 중 개선 가능한 부분 `a`가 작으면, 일부를 아무리 최적화해도 전체 향상은 제한된다.
- 병목이 어디인지 먼저 찾는 것이 최적화의 출발점이다.

---

## 8. 동시성과 병렬성

- **동시성**: 여러 일이 겹쳐 진행되는 성질
- **병렬성**: 동시성을 이용해 실제 처리 속도를 높이는 방법
- 예: 스레드 수준 동시성, 명령어 수준 병렬성, SIMD
