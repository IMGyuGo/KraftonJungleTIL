# CSAPP 정리

## 1) 프로그램 번역 과정

`hello.c` 같은 C 소스는 여러 단계를 거쳐 실행 가능한 목적 파일로 변환된다.

1. 전처리(Preprocessing, `cpp`)
   - `#include`, `#define` 같은 디렉티브를 처리해 소스 코드를 확장한다.
2. 컴파일(Compilation)
   - 전처리된 C 코드를 어셈블리 코드로 변환한다.
3. 어셈블(Assembly)
   - 어셈블리 코드를 기계어 목적 파일로 변환한다.
4. 링크(Linking)
   - 라이브러리/다른 목적 파일과 결합해 최종 실행 파일을 만든다.

---

## 2) 컴파일 시스템 이해가 중요한 이유

### 성능 최적화 관점

- `switch` vs `if-else`, `for` vs `while`처럼 문법 형태만으로 성능을 단정하면 안 된다.
- 함수 호출 오버헤드, 메모리 접근 방식(포인터/배열), 수식 재배치까지 성능에 영향을 준다.

### 링크/빌드 에러 관점

- 심볼(함수/변수) 해석 실패가 무엇인지 이해해야 에러를 정확히 디버깅할 수 있다.
- 정적/전역 변수 차이, 정적 라이브러리 vs 동적 라이브러리 차이, 라이브러리 링크 순서가 중요하다.

### 보안 관점

- 버퍼 오버플로우는 입력 데이터의 크기/형태 검증 부족에서 자주 발생한다.
- 스택에 데이터와 제어 정보가 저장되는 방식을 이해해야 취약점을 줄일 수 있다.

## 3) 전형적인 시스템 하드웨어 구성

- **버스(Bus)**: CPU, 메모리, I/O 장치 간 데이터 이동 통로
- **입출력 장치(I/O Device)**: 키보드, 디스크, 네트워크 등 외부와 데이터 교환
- **메인 메모리(Main Memory)**: 실행 중인 코드와 데이터를 저장
- **프로세서(CPU)**: 명령어를 읽고 해석/실행
  - PC(Program Counter)는 다음에 실행할 명령어 위치를 가리킨다.
  - ALU는 산술/논리 연산을 수행한다.

### CPU의 기본 동작

- **Load**: 메모리 -> 레지스터
- **Store**: 레지스터 -> 메모리
- **Operate**: ALU 연산 후 결과를 레지스터에 저장
- **Jump**: PC를 갱신해 실행 흐름을 변경

---

## 4) 운영체제 핵심 추상화

### 프로세스(Process)

- 실행 중인 프로그램 단위
- 컨텍스트(PC, 레지스터 상태, 메모리 상태)를 가진다.
- OS는 컨텍스트 스위칭으로 프로세스 간 CPU 제어권을 전환한다.

### 스레드(Thread)

- 한 프로세스 내 실행 흐름 단위
- 코드/전역 데이터를 공유하면서 각자 실행된다.

### 가상 메모리(Virtual Memory)

- 각 프로세스가 큰 연속 메모리를 독점적으로 쓰는 것처럼 보이게 하는 추상화
- 사용자 영역과 OS 공용 영역이 논리적으로 분리된다.

---

## 5) Amdahl의 법칙

병렬화/최적화의 한계를 설명한다.

- `T(new) = (1-a)T(old) + (aT(old))/k`
- 가속비: `T(old)/T(new) = 1 / ((1-a) + a/k)`

의미:

- 전체 중 개선 가능한 비율 `a`가 작으면, 일부만 아무리 빨라져도 전체 속도 향상은 제한된다.
