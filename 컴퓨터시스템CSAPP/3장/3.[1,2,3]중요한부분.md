# ✅ 3.1 역사적 관점 (Historical Perspective)

👉 “왜 지금 구조가 이렇게 되었는가?”를 이해하는 파트

### 🔥 핵심 포인트

- **Intel x86 아키텍처의 진화 흐름**
  - 8086 → IA-32 → x86-64

- **32비트 → 64비트로 확장되면서 바뀐 것**
  - 레지스터 수 증가
  - 주소 공간 증가
  - 성능 개선

### 💡 중요한 이유

- 단순 역사 아님 → **현재 구조를 이해하기 위한 배경**
- 특히:
  - 왜 레지스터 이름이 이상한지 (`eax`, `rax`)
    - 초기 Intel 8086에서는 이름이 굉장히 직관적이었음
      - AX -> Accumulator (계산용)
      - BX -> Base (주소 계산용)
      - CX -> Counter (루프 카운터)
      - DX -> Data (데이터용)
    - 16 비트 -> 32 비트로 확장되면서 이름이 바뀜
      - AX -> EAX (Extended AX)
      - BX -> EBX
      - CX -> ECX
      - DX -> EDX
    - 32 비트 -> 64 비트 확장
      - EAX -> RAX
      - EBX -> RBX
      - ECX -> RCX
      - EDX -> RDX
    ```
    RAX (64bit)
    └ EAX (32bit)
        └ AX (16bit)
          ├ AH (상위 8bit)
          └ AL (하위 8bit)
    ```
  - 왜 하위 호환이 중요한지 - 과거에 만든 프로그램이 현재에도 잘 돌아가야 한다는 개념
    👉 결론:

> ❗ “x86 구조는 과거와의 호환성을 유지하면서 확장된 구조다”

# ✅ 3.2 프로그램의 인코딩 (Program Encoding)

👉 “C 코드 → 어셈블리 → 기계어”로 변환되는 과정

---

## 🔥 핵심 1: 컴파일 과정 전체 흐름

```
C 코드 → (컴파일러) → 어셈블리 → (어셈블러) → 오브젝트 파일 → (링커) → 실행 파일
```

👉 반드시 이해해야 함:

- 컴파일 / 어셈블 / 링크 역할 구분

---

## 🔥 핵심 2: 어셈블리 구조

### 예시 개념

```asm
movq %rax, %rbx
```

### 중요 요소

- **레지스터 (%rax, %rbx)**
- **명령어 (movq, addq 등)**
- **오퍼랜드 위치**
  - 연산에 필요한 값이 어디에 있는지 (레지스터/메모리/즉시값)
  - 먼저 어셈블리 한 줄을 보면
    - 구성 :
      - movq : 명령어 (무엇을 할지)
      - %rax, %rbx : 오퍼랜드 (값)
      - 중요한 건 '값 자체'가 아니라 값이 어디에 저장되어 있는지가 핵심

  ```
  대표 3가지

  1. 레지스터
  addq %rax, %rbx
  %rax : 값이 레지스터에 있음
  %rbx : 결과 저장 위치

  2. 메모리
  movq (%rax), %rbx
  (%rax) : 메모리 주소에 있는 값
  %rbx : 레지스터

  의미 : rax가 가리키는 주소에서 값 가져옴

  3. 즉시 값 (상수)
  movq $10, %rax
  $10 : 숫자 그 자체

  의미 : 10을 rax에 넣어라
  ```

👉 질문했던 것 연결:

> `%rbx` = **CPU 내부 레지스터**

---

## 🔥 핵심 3: 레지스터 구조

### x86-64 주요 레지스터

- `%rax`, `%rbx`, `%rcx`, `%rdx`
- `%rsp` (스택 포인터)
- `%rbp` (베이스 포인터)

👉 매우 중요:

- 함수 호출 / 스택 이해할 때 핵심

---

## 🔥 핵심 4: 프로그램 카운터 (PC / RIP)

- `%rip` = 현재 실행 중인 명령어 위치
- 다음 실행 위치 결정

👉 핵심:

> ❗ “CPU는 항상 RIP 기준으로 다음 명령을 실행한다”

---

## 🔥 핵심 5: 데이터 이동과 연산

- `mov`, `add`, `sub`, `imul`
- 메모리 ↔ 레지스터 이동

👉 중요한 이유:

- C 코드가 어떻게 변환되는지 이해 가능

# ✅ 3.3 데이터 형식 (Data Formats)

👉 “데이터가 메모리에서 어떻게 저장되는가”

---

## 🔥 핵심 1: 바이트와 워드 개념

- 1 byte = 8 bits
- word 크기:
  - 32bit → 4 bytes
  - 64bit → 8 bytes

---

## 🔥 핵심 2: 자료형 크기 (진짜 중요)

| 타입    | 크기             |
| ------- | ---------------- |
| char    | 1 byte           |
| int     | 4 bytes          |
| long    | 8 bytes (x86-64) |
| pointer | 8 bytes          |

👉 중요 이유:

- 메모리 계산
- 배열, 구조체 이해

---

## 🔥 핵심 3: 리틀 엔디안 (Little Endian)

👉 핵심 개념:

- **낮은 주소에 LSB 저장**

예:

```
0x12345678
→ 메모리: 78 56 34 12
```

👉 매우 중요:

- 디버깅 / 메모리 분석 / 네트워크 이해

---

## 🔥 핵심 4: 부호 있는 정수 표현 (2의 보수)

👉 핵심:

- 음수는 2의 보수로 표현

```
-1 → 11111111
```

👉 중요한 이유:

- overflow 이해
- signed vs unsigned 차이

---

## 🔥 핵심 5: 부동소수점 (간단히)

- IEEE 754
- 실수는 정확하지 않음

👉 핵심 메시지:

> ❗ “float/double은 근사값이다”
