- tiny.out에 찍힌 결과를 보고 이게 무엇인지 해석하는 것

```
검색해보니
현재는 RCF 9110 (semantics), RFC 9112 (HTTP/1.1) RFC 9113 (HTTP/2), RFC 9114(HTTP/3)이다.
이미 대체가 다 되었기 때문에 좀 더 다른 방식으로 접근 (알아야 할 정보들만 조사)

- method + path + HTTP version : 뭥ㅅ을, 어디에, 어떤 HTTP 버전으로 요청하는지

- Host : 어떤 호스트와 포트로 향한 요청인지 (HTTP/1.1에선 필수 -> 가상 호스팅을 구분할 때 핵심)
- Accept : 클라이언트가 어떤 응답을 받고 싶은지 (MIME 타입)
- Content-Type : 요청 바디가 있을 때, 그 바디의 형식. POST나 PUT 디버깅에서 가장 중요하고, 서버가 엄격하면 잘못된 타입에 415를 줄 수 있음
- Authorization : 인증 정보
- Cookie : 세션/로그인 상태 같은 클라이언트 저장 값이 서버로 넘어오는 자리
- Origin : 요청이 어느 출처에서 시작됐는지 보여줌 (경로는 포함하지 않고, CORS나 CSRF 관련 판단에서 중요)
- Referer : 사용자가 어떤 페이지에서 이 요청으로 넘어왔는지 보여줌. Origin보다 더 많은 정보가 들어갈 수 있지만, fragment와 사용자 정보는 포함하지 않음
- Accept-Encoding : 어떤 압축을 받을 수 있는지. 요즘 브라우저는 gzip, br, zstd등을 보낼 수 있어서 서버.프록시가 압축 현상을 이해하는 데 중요
- Accept-Language : 사용자가 선호하는 언어
- Sec-Fetch-Site, Sec-Fetch-Mode, Sec-Fetch-Dest : 요즘 브라우저에서 특히 유용한 "요청 맥락" 헤더.
- User-Agent, Sec_CH-UA* : 클라이언트 종류를 대략 파악할 때 봄. 다만 MDN도 UA 기반 브라우저 판별은 보통 좋지 않다고 경고하고, Sec-CH-UA는 제한적 지원과 HTTPS 조건이 있음.
- Cache-Control, If-None-Match : 캐시 디버깅에서 핵심. 특히 If-None-Match는 ETag 기반 조건부 요청이라 304 Not Modified가 왜 나는지 이해할 때 중요
- Range : 파일 일부만 달라고 할 때 쓰임. 다운로드 재개, 스트리밍, 부분 응답(206)과 연결
```

## - 프록시 서버

- web proxy 구현은 단순히 "요청 전달"이 아니라 `네트워크 + HTTP + 시스템 프로그래밍 + 성능 최적화`가 다 들어가는 것
- 기본적인 흐름

### 1. 전체 구조

```
Client <-> Proxy <-> Server
클라이언트 요청을 바고, 서버에 대신 요청 보내고 응답을 받아서 다시 클라이언트에게 전달
```

### 2. 소켓 프로그래밍 (기본 뼈대)

```
프록시에서 중요한 포인트
1. 클라이언트 연결 받음
connfd = accept()

2. 서버에 연결
serverfd = connect()

3. 데이터 중계
client -> proxy -> server
server -> proxy -> client
```

### 3. HTTP 프로토콜 이해 (핵심 중 핵심)

- 1. 요청 구조

```
GET http://example.com/index.html HTTP/1.1
Host: example.com
User-Agent: ...
Connection: keep-alive
```

- 2. 프록시에서 해야 할 일

```
- URL 파싱
http://example.com:80/index.html
-> host : example.com
-> port : 80
-> path : /index.html

- 헤더 수정
Connection: close
Proxy-Connection: close

persistent connection 끊고 단순하게 처리하려고
```

### 4. I/O 모델 (여기서 성능 갈림)

- 1. Iterative (단일 처리)
  - 한 번에 한 클라이언트
  - 구현 쉬운 대신 느림

- 2. Concurrent (멀티 프로세스 / 스레드)

```
While(1) {
    connfd = accept();

}
```

- 3. Event-Driven (select / epoll)

```
- 고성능 서버 방식

```

```

### 6. Caching (Proxy의 핵심 기능)

  - 여러 클라이언트가 같은 캐시 접근

- waitpid()

```
pid_t waitpid(pid_t pid, int *statloc, int options);

성공 : 프로세스 ID 반환
실패 : -1

-> pid == -1
임의의 자식 프로세스를 기다림

-> pid > 0
프로세스 ID가 pid인 자식 프로세스를 기다림

-> pid == 0
waitpid를 호출한 프로세스의 프로세스 그룹 PID와 같은 프로세스 그룹 ID를 가진 프로세스를 기다림

options
-> WNOHANG
기다리는 PID가 종료되지 않아서 즉시 종료 상태를 회수 할 수 없는 상황에서 호출자는 차단되지 않고 반환값으로 0을 받음

- stat()

```
int stat(const char* path, struct stat *buf);

파일의 크기, 권한, 생성일시, 최종 변경일 등 파일의 상태나 파일의 정보를 얻는 함수
symbolic link인 파일을 path로 넘기면 그 원본 파일의 정보를 얻음.

struct stat {
    dev_t st_dev; // 파일이 존재하는 디바이스 ID
    ino_t st_ino; // indoe 번호 (파일 고유 식별자)

- dup2()

```
유닉스 및 유닉스 계열 운영체제에서 파일 디스크립터를 복제하는 시스템 콜(운영체제 커널이 제공하는 서비스를 사용하기 위해 애플리케이션이 커널에게 요청하는 인터페이스)

-> ex

STDOUT_FILENO
STDIN_FILENO
STDERR_FILENO

Dup2(fd, STDOUT_FILENO)는 "STDOUT_FILENO가 가리키는 대상을 fd와 같게 바꾼다"는 뜻
즉 serve_dynamic의 자식 프로세스에서 이걸 해두면, 그 다음 execve()로 실행된 CGI 프로그램의 표준출력 stdout이 클라이언트 소켓으로 연결됨. 그래서 CGI가 printf("Content-type: text/html\r\n\r\n...")를 하면 그 내용이 브라우저로 감.

조금 더 정확히 말하면 dup2(oldfd, newfd)는 newfd를 닫고, 그 번호가 oldfd와 같은 열린 파일을 가리키게 만듬.
예를 들어 fd가 소켓 5이고 STDOUT_FILENO가 1이면, 실행 뒤에는 1번이 소켓을 가리키게 됨. 그러면 write(1, ...), printf(...), puts(...)가 전부 소켓으로 나감. 이후 fd 자체는 닫아도 되고, 1번이 살아 있으니 출력은 계속 가능.

STDOUT_FILENO 말고도 대표적으로 3개가 있습니다.

STDIN_FILENO = 0
STDOUT_FILENO = 1
STDERR_FILENO = 2
그래서 이런 것도 가능합니다.

Dup2(fd, STDIN_FILENO)
클라이언트 소켓을 표준입력으로 연결
Dup2(fd, STDOUT_FILENO)
클라이언트 소켓을 표준출력으로 연결
Dup2(fd, STDERR_FILENO)
에러 출력도 같은 소켓으로 보내기

## 5. Proxy 필수 함수 정리

- pthread_create()

```
int pthread_create(pthread_t *restrict thread,
                   const pthread_attr_t *restrict attr,
                   void *(*start_routine)(void *),
                   void *restrict arg);

pthread_t *restrict thread : 스레드의 식별자
const pthread_attr_t *restrict attr : 설정할 스레드 속성정보(NULL 입력시 기본설정 적용)
void *(*start_routine)(void *) : 스레드가 실행할 함수
void *restrict arg : 스레드가 실행할 함수에 들어갈 인자

- attr 정보
Thread attributes :
    Detach state        = PTHREAD_CREATE_JOINABLE
    Scope               = PTHREAD_SCOPE_SYSTEM
    Inherit scheduler   = PTHREA_INHERIT_SCHED
    Scheduling policy   = SCHED_OTHER
    Scheduling priority = 0
    Guard size          = 4096 bytes
    Stack address       = 0x40196000
    Stack size          = 0x201000 bytes


함수 호출 시 새 스레드가생 생성되고, 생성된 스레드는 start_routine(arg)를 실행
생성된 스레드는 다음 세 가지 경우 종료
- pthread_exit() 호출
- start_routine() 수행 후 return
- pthread_cancel() 호출

return
- 성공 시 0을 반환하고 스레드의 식별자를 thread_t에 담음
- 오류 발생 시 오류 번호를 반환하고 thread_t를 정의하지 않음

- ERRORS
    - EAGAIN : 리소스가 부족해 다른 스레드를 만들 수 없음
    - EINVAL : attr의 설정이 잘못 됨, 스레드 수가 제한을 넘음
    - EPERM : attr에 지정된 스케줄링 정책 및 매개 변수를 설정할 수 있는 권한이 없음
```
