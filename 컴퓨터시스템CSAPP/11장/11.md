## 11.2 네트워크

- 네트워크 -> 네트워크 어댑터 -> 버스 I/O -> 메모리 버스 -> DMA 접근 (Direct Memory Access)

- Host A -> Host B 로의 전달 과정
  - 1. Host A의 프로세스가 데이터를 보내려고 하면, 시스템 콜을 통해 커널이 네트워크 I/O를 처리한다.
  - 2. 전송할 데이터는 상위 계층 정보가 붙은 packet 이 되고, 실제 링크(Ethernet 등)를 타기 위해 frame 으로 한 번 더 감싸진다.
  - 3. 이 frame이 네트워크를 따라 전달되고, 중간 장비는 목적지 정보를 보고 다음 경로로 넘긴다.
  - 4. Host B 쪽에 도착하면 바깥쪽 frame이 벗겨지고, 필요한 계층 정보를 해석한 뒤 최종적으로 Host B의 해당 프로세스까지 전달된다.
  - 실제로는 이것보다 엄청 많은 자세한 세부 내용이 있다.

- 생각해볼 수 있는 이슈들
  - 1. 만일 서로 다른 네트워크들이 서로 다른 최대 프레임을 갖는다면?
  - 2. 라우터들은 어디로 프레임을 전달해야 할지 어떻게 알지?
  - 3. 라우터들은 언제 네트워크 구조가 변경되는지 어떻게 알아내지?
  - 4. 패킷이 손실된다면?

### 11.4.1 소켓 주소 구조체

`책을 보면, 이 내용은 구조체 정의와 전체 소켓 인터페이스 참조 개요를 볼 수 있다.`

- Unix 프로그램 관점에서 보면 소켓은 해당 식별자를 가지는 열린 파일

### 11.4.2 socket 함수

- 클라이언트와 서버는 소켓 식별자를 생성하기 위해 socket 함수를 사용

- 만약 소켓을 끝점으로 만들고 싶다면, 아래와 같이

```
clientfd = Socket(AF_INET, SOCK_STREAM, 0);
```

- 위 과정에 의해 리턴된 clientfd 식별자는 겨우 부분적으로 오픈된 것

### 11.4.3 connect 함수

- 클라이언트는 connect 함수를 호출해서 서버와의 연결을 수립

- 소켓 주소 addr의 서버와 인터넷 연결을 시도하며, addrlen은 sizeof(sockaddr_in)
- connect함수는 연결이 성공할 때까지 블록되어 있거나 에러가 발생
- 만일 성공이라면, clientfd 식별자는 이제 읽어나 쓸 준비가 되었다는 의미로 소켓 쌍으로 규정
  - (x:y, addr.sin_addr:addr.sin_port)
  - 여기서 x는 클라이언트의 IP 주소이고, y는 클라이언트 호스트의 클라이언트 프로세스를 유일하게 식별하는 단기 포트

### 11.4.4 bind 함수

- 서버가 클라이언트와 연결을 수립하기 위해 사용
- addrlen 인자는 sizeof(sockaddr_int)

### 11.4.5 listen 함수

- 클라이언트는 연결 요청을 개시하는 능동적인 개체이고, 서버는 클라이언트로부터의 연결 요청을 기다리는 수동 개체
- 기본적으로 커널은 socket 함수가 만든 식별자는 한 연결의 클라이언트 쪽 끝에서 존재하는 능동 소켓에 대응
- 서버는 listen 함수를 호출해서 이 식별자를 클라이언트 대신에 서버가 사용하게 될 것이라고 알려줌
- backlog는 커널이 요청들을 거절하기 전 큐에 저장해야 하는 연결의 수에 대한 정보를 제공 (1024)
  - 커널은 완료된 연결(accept 대기 상태)을 큐에 저장하는데, 그 큐의 크기가 backlog이다.
  - 동시에 최대 1024개의 연결 요청을 "대기" 가능 이라는 의미

### 11.4.6 accept 함수

- 클라이언트로부터 연결 요청이 듣기 식별자 listenfd에 도달하기를 기다리고, 그 후에 addr 내의 클라이언트의 소켓 주소를 채우고, Unix I/O 함수들을 사용해서 클라이언트와 통신하기 위해 사용될 수 있는 연결 식별자를 리턴
- 듣기 식별자 : 클라이언트 연결 요청에 대해 끝점으로서의 역할 (서버가 살아있는 동안 계속 존재)
- 연결 식별자 : 클라이언트와 서버 사이에 연결된 연결의 끝점

### 11.5.4 동적 컨텐츠의 처리

- CGI (Common Gateway Interface)
  - How client sends a program instances to server?

  ```
  요청
  GET /cgi-bin/adder?15000&213 HTTP/1.1

  1. fork를 호출해서 자식 프로세스를 생성하고, execve를 호출해서 /cgi-bin/adder 프로그램을 자식의 컨텍스트에서 실행
  2. adder 같은 프로그램들은 종종 CGI 프로그램이라고 부름
    - 이들이 CGI 표준의 규칙을 준수하기 때문
  3. execve를 호출하기 전 자식 프로세스는 CGI 환경변수 QUERY_STRING을 "15000&213"으로 설정하고, adder 프로그램은 런 타임에 리눅스 getenv 함수를 사용해 이 값을 참조 가능
  ```

  - CGI 규칙이란? - 웹 서버와 외부 프로그램(예: C 프로그램, Python 스크립트)이 서로 데이터를 주고받는 약속(인터페이스 규칙)

  ```
  <입력 - 환경 변수 + 표준 입력(stdin)>
  - 서버 처리
    setenv("QUERY_STRING", "15000&213", 1);
  - 프로그램 Read
    char* query = getenv("QUERY_STRING");

  <출력 - 표준 출력(stdout)>
  - 그냥 printf()
  ```

  | 환경 변수           | 설명                                                              |
  | ------------------- | ----------------------------------------------------------------- |
  | **QUERY_STRING**    | URL에서 `?` 뒤에 붙는 쿼리 문자열 (GET 요청 데이터)               |
  | **REQUEST_METHOD**  | HTTP 요청 방식 (예: GET, POST)                                    |
  | **CONTENT_LENGTH**  | POST 요청에서 전달된 데이터의 길이 (바이트 단위)                  |
  | **CONTENT_TYPE**    | 요청 본문의 데이터 타입 (예: `application/x-www-form-urlencoded`) |
  | **SCRIPT_NAME**     | 실행되는 CGI 프로그램의 경로                                      |
  | **SERVER_NAME**     | 서버의 호스트 이름                                                |
  | **SERVER_PORT**     | 서버가 사용하는 포트 번호                                         |
  | **SERVER_PROTOCOL** | 사용된 프로토콜 (예: HTTP/1.0, HTTP/1.1)                          |
  | **REMOTE_ADDR**     | 클라이언트의 IP 주소                                              |

- mmap()함수란

```
mmap은 메모리를 어떤 파일 혹은 디바이스에 대응시키는 함수
컴퓨터 프로세스에서 각 프로세스는 다른 프로세스와 분리된 주소를 가지고 있어 서로 겹치지 않는다.
즉, 프로세스 메모리는 서로 중복되지 않는다. 그렇기 때문에 프로세스 간 데이터 공유가 어렵다.

mmap을 이용하면 공유하고자 하는 메모리를 아예 파일로 대응시켜놓고, 이를 여러 프로세스가 사용할 수 있게 함 - 파일은 전역적인 개체이기 때문

- 서로 다른 프로세스 간 데이터 공유를용이하게 하는 것
- 저장 매체 접근 대신 메모리에 접근할 수 있게하여 성능이 향상

void *mmap(void *start, size_t length, int prot, int flags, int fd, off_t offset);

void* start - 메모리 시작위치
보통 NULL(0)로 설정해 커널이 알아서 위치 설정하도록 함

size_t length - 할당할 메모리 길이

int prot - 맵핑에 원하는 메모리 보호 정책 (ex: 읽기 전용으로 열었다면 PROT_WRITE를 지정하면 안됨)
- PROT_READ(읽기 가능)
- PROT_WRITE(쓰기 가능)
- PROT_EXEC(실행 가능)
- PROT_NONE(접근 불가)

int flags - 메모리 주소 공간 설정 (메모리를 어디에 생성할 것인지 설정)
- MAP_SHARED(다른 프로세스와 공유가능 / 프로세스 외부 생성)
- MAP_PRIVATE(프로세스 내에서만 사용 / 프로세스 내부 생성)
- MAP_FIXED(지정된 주소로 공간지정 / 지정된 공간에 생성)
- MAP_ANONYMOUS(어떤 파일과도 매핑되지 않음)
  - addr=0, fd=-1(혹은 무시)로 설정, offset=0

int fd - 어떤 파일을 매핑시킬 것인지 file descriptor 지정 (open 함수가 반환하는 애)

off_t offset - 시작주소(start)를 기준으로 얼만큼 떨어진 곳에 생성할 것인지?

return value - 매핑된 메모리 위치
```
