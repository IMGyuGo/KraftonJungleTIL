## 11.2 네트워크

- 네트워크 -> 네트워크 어댑터 -> 버스 I/O -> 메모리 버스 -> DMA 접근 (Direct Memory Access)

- Host A -> Host B 로의 전달 과정
  - 1. Host A의 프로세스가 데이터를 보내려고 하면, 시스템 콜을 통해 커널이 네트워크 I/O를 처리한다.
  - 2. 전송할 데이터는 상위 계층 정보가 붙은 packet 이 되고, 실제 링크(Ethernet 등)를 타기 위해 frame 으로 한 번 더 감싸진다.
  - 3. 이 frame이 네트워크를 따라 전달되고, 중간 장비는 목적지 정보를 보고 다음 경로로 넘긴다.
  - 4. Host B 쪽에 도착하면 바깥쪽 frame이 벗겨지고, 필요한 계층 정보를 해석한 뒤 최종적으로 Host B의 해당 프로세스까지 전달된다.
  - 실제로는 이것보다 엄청 많은 자세한 세부 내용이 있다.

- 생각해볼 수 있는 이슈들
  - 1. 만일 서로 다른 네트워크들이 서로 다른 최대 프레임을 갖는다면?
  - 2. 라우터들은 어디로 프레임을 전달해야 할지 어떻게 알지?
  - 3. 라우터들은 언제 네트워크 구조가 변경되는지 어떻게 알아내지?
  - 4. 패킷이 손실된다면?

## 11.4 소켓 인터페이스

- 네트워크 응용을 만들기 위한 Unix I/O 함수들과 함께 사용되는 함수들의 집합
  - 모든 Unix 변종, 윈도우, 매킨토시 시스템을 포함하는 대부분의 현대 시스템에서 구현

### 11.4.1 소켓 주소 구조체

`책을 보면, 이 내용은 구조체 정의와 전체 소켓 인터페이스 참조 개요를 볼 수 있다.`
`따로 정의는 하지 않을 것`

- 리눅스 커널의 관점에서 보았을 때, 소켓은 통신을 위한 끝점
- Unix 프로그램 관점에서 보면 소켓은 해당 식별자를 가지는 열린 파일

### 11.4.2 socket 함수

- 클라이언트와 서버는 소켓 식별자를 생성하기 위해 socket 함수를 사용

- 만약 소켓을 끝점으로 만들고 싶다면, 아래와 같이

```
clientfd = Socket(AF_INET, SOCK_STREAM, 0);
```

- 위 과정에 의해 리턴된 clientfd 식별자는 겨우 부분적으로 오픈된 것

### 11.4.3 connect 함수

- 클라이언트는 connect 함수를 호출해서 서버와의 연결을 수립

- 소켓 주소 addr의 서버와 인터넷 연결을 시도하며, addrlen은 sizeof(sockaddr_in)
- connect함수는 연결이 성공할 때까지 블록되어 있거나 에러가 발생
- 만일 성공이라면, clientfd 식별자는 이제 읽어나 쓸 준비가 되었다는 의미로 소켓 쌍으로 규정
  - (x:y, addr.sin_addr:addr.sin_port)
  - 여기서 x는 클라이언트의 IP 주소이고, y는 클라이언트 호스트의 클라이언트 프로세스를 유일하게 식별하는 단기 포트

### 11.4.4 bind 함수

- 서버가 클라이언트와 연결을 수립하기 위해 사용
- addrlen 인자는 sizeof(sockaddr_int)

### 11.4.5 listen 함수

- 클라이언트는 연결 요청을 개시하는 능동적인 개체이고, 서버는 클라이언트로부터의 연결 요청을 기다리는 수동 개체
- 기본적으로 커널은 socket 함수가 만든 식별자는 한 연결의 클라이언트 쪽 끝에서 존재하는 능동 소켓에 대응
- 서버는 listen 함수를 호출해서 이 식별자를 클라이언트 대신에 서버가 사용하게 될 것이라고 알려줌
- backlog는 커널이 요청들을 거절하기 전 큐에 저장해야 하는 연결의 수에 대한 정보를 제공 (1024)
  - 커널은 완료된 연결(accept 대기 상태)을 큐에 저장하는데, 그 큐의 크기가 backlog이다.
  - 동시에 최대 1024개의 연결 요청을 "대기" 가능 이라는 의미

### 11.4.6 accept 함수

- 클라이언트로부터 연결 요청이 듣기 식별자 listenfd에 도달하기를 기다리고, 그 후에 addr 내의 클라이언트의 소켓 주소를 채우고, Unix I/O 함수들을 사용해서 클라이언트와 통신하기 위해 사용될 수 있는 연결 식별자를 리턴
- 듣기 식별자 : 클라이언트 연결 요청에 대해 끝점으로서의 역할 (서버가 살아있는 동안 계속 존재)
- 연결 식별자 : 클라이언트와 서버 사이에 연결된 연결의 끝점
