5. 페이지 폴트(Page Fault)의 개념을 설명하고, 페이지 폴트가 발생했을 때 운영체제가 수행하는 절차를 본인이 이해한 만큼 자세히 서술하시오.

```
Page Fault란
먼저 메모리의 크기가 동적메모리의 페이지 사이즈인 4096Byte를 기준으로 삼고 2가지로 나눈다면
현재 페이지 단위인 CHUNKSIZE 보다 작게 값이 들어오는 경우는 정상적인 작동
현재 페이지 단위인 CHUNKSIZE 보다 값이 크게 들어오는 경우를 Page Fault라고 한다.

이 경우 Page 보다 임시적으로 더 큰 사이즈를 새롭게 힙 메모리에 할당해 힙이 사용할 수 있는 공간을 늘린 후 현재 블럭과 다음 블럭을 합쳐 Page Fault된 사이즈 범위를 가진 블럭에 할당하는 과정을 운영체제가 수행한다.
```

```
페이지 폴트란?

페이지 폴트는 프로그램이 어떤 가상 주소에 접근했는데, 그 주소에 해당하는 페이지가 현재 물리 메모리(RAM)에 없거나, 접근 권한이 맞지 않을 때 발생하는 예외다.

쉽게 말하면:

CPU가 어떤 주소를 읽거나 쓰려고 함
MMU가 페이지 테이블을 봄
그런데 그 페이지가 메모리에 없거나 접근 불가
그러면 페이지 폴트 예외가 발생
운영체제가 개입해서 처리
언제 발생하나?

대표적으로:

필요한 페이지가 아직 RAM에 올라오지 않았을 때
디스크의 스왑 영역에 있던 페이지를 다시 가져와야 할 때
처음 접근하는 가상 메모리 영역일 때
읽기 전용 페이지에 쓰기를 시도했을 때
아예 잘못된 주소 접근일 때

운영체제가 수행하는 절차
1. CPU가 페이지 폴트 예외를 발생시킴
  접근하려던 가상 주소와 접근 종류(읽기/쓰기)가 기록됨
2. 운영체제가 해당 주소가 유효한지 확인
  프로세스가 접근 가능한 주소인지 검사
  아예 잘못된 주소면 프로세스를 종료하거나 오류 처리
  예: segmentation fault
3. 유효한 주소라면 해당 페이지의 위치를 확인
  디스크 파일, 실행 파일, swap 영역 등 어디에 있는지 확인
4. 빈 물리 프레임을 찾음
  RAM에서 빈 프레임을 찾음
  없으면 페이지 교체 알고리즘으로 희생 페이지 선택
  예: LRU, Clock 등
5. 필요하면 희생 페이지를 디스크에 기록
  더티 페이지라면 디스크에 저장 후 교체
6. 요청한 페이지를 디스크에서 RAM으로 읽어옴
  페이지 전체를 물리 프레임에 적재
7. 페이지 테이블 갱신
  해당 가상 페이지가 이제 어느 물리 프레임에 있는지 기록
  valid bit 등 상태도 갱신
8. 중단되었던 명령어를 다시 실행
  프로세스는 마치 원래부터 페이지가 있었던 것처럼 계속 실행됨

페이지 폴트(Page Fault)란 프로세스가 접근하려는 가상 메모리 페이지가 현재 물리 메모리에 존재하지 않거나, 접근 권한이 없는 경우 발생하는 예외이다.

페이지 폴트가 발생하면 운영체제는 먼저 해당 주소가 프로세스의 유효한 주소인지 검사한다.
만약 유효하지 않은 주소라면 프로세스를 종료하거나 예외 처리한다.
유효한 주소라면, 운영체제는 그 페이지가 디스크의 어디에 저장되어 있는지 확인한 뒤 빈 물리 프레임을 찾는다.
빈 프레임이 없으면 페이지 교체 알고리즘을 통해 기존 페이지를 내보내고, 필요한 경우 수정된 페이지를 디스크에 기록한다.
이후 필요한 페이지를 디스크에서 메모리로 읽어와 페이지 테이블을 갱신하고, 중단되었던 명령어를 다시 실행한다.
```

6. C 언어에서는 malloc() 함수를 이용해 동적으로 메모리를 할당받을 수 있다. 그렇다면 굳이 mmap() 시스템 호출을 사용하여 메모리를 할당받는 이유는 무엇인지 설명하시오.

```
malloc()
C 라이브러리 함수
사용하기 편한 일반적인 동적 메모리 할당 도구
내부적으로 힙(heap)을 사용
필요하면 내부에서 brk/sbrk 또는 mmap을 이용해 운영체제에 메모리를 요청함

즉, malloc()은 네가 직접 OS와 이야기하는 게 아니라, 라이브러리 관리자를 통해 빌리는 방식이야.

mmap()
시스템 호출
파일 또는 익명 메모리를 가상 메모리 공간에 직접 매핑
메모리 영역을 페이지 단위로 직접 다루는 데 유리
더 큰 제어권을 가짐

즉, mmap()은 운영체제에게 직접 메모리 영역을 매핑해 달라고 요청하는 방식이야.

<mmap을 쓰는 이유>
1. 큰 메모리를 효율적으로 할당하기 위해

큰 메모리를 malloc()으로만 처리하면 힙 조각화 문제가 생길 수 있다.
mmap()은 큰 메모리 블록을 별도 영역으로 매핑하므로:

힙과 분리 가능
반환 시 munmap()으로 즉시 OS에 돌려주기 쉬움
큰 블록 관리가 깔끔함

실제로 많은 malloc 구현도 큰 할당은 내부적으로 mmap 사용한다.

2. 파일을 메모리처럼 다루기 위해

mmap()의 가장 큰 특징 중 하나는 파일 매핑이다.

예를 들어 큰 파일을 읽을 때:

read()로 버퍼에 복사하는 대신
파일을 메모리에 매핑해서
배열처럼 접근 가능

장점:

복사 비용 감소
필요한 페이지들만 실제로 로드됨
랜덤 접근이 편함

3. 페이지 단위 제어가 가능해서

mmap()은 페이지 단위로 메모리를 할당하므로:

보호 권한 설정 가능 (PROT_READ, PROT_WRITE, PROT_EXEC)
공유 메모리 구성 가능
프로세스 간 메모리 공유 가능
특정 주소에 매핑도 가능

즉, 단순히 "메모리 좀 주세요"가 아니라
"이 메모리를 읽기 전용으로, 또는 여러 프로세스가 함께 보게" 같은 식의 제어가 가능하다.

4. 메모리를 OS에 바로 반납하기 쉬움

malloc()은 free()를 해도 메모리가 항상 즉시 OS에 반환되는 건 아니다.
보통 할당기 내부 풀에 남아 재사용될 수 있다.

5. 공유 메모리로 사용 가능

mmap()은 여러 프로세스가 같은 파일 또는 익명 공유 메모리를 같이 볼 수 있게 할 수 있다.

예를 들어:

프로세스 간 통신(IPC)
공유 캐시
고속 데이터 전달

같은 데 활용 가능하다.

malloc()은 기본적으로 한 프로세스 내부 힙에서만 의미가 있다.

6. 그럼 malloc만 쓰면 안 되나?

일반적인 프로그램에서는 대부분 malloc()이면 충분하다.

왜냐하면:

사용이 간단하고
타입 맞춰 쓰기 쉽고
관리가 편하고
작은/일반적인 동적 할당에 적합하기 때문

하지만 아래 같은 경우엔 mmap()이 더 적합하다:

매우 큰 메모리 블록
파일 매핑
공유 메모리
메모리 보호 권한 제어
커스텀 메모리 할당기 구현
DB, 캐시 서버, VM, 런타임, 브라우저 같은 시스템 수준 프로그램
```

- malloc
  - 일반적인 동적 할당
  - 편리함
  - 힙 기반
  - 세부 제어 적음
- mmap
  - OS 수준 매핑
  - 큰 메모리/파일/공유 메모리에 강함
  - 페이지 단위 제어 가능
  - 더 직접적이고 강력함
