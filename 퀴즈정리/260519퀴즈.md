```

유저 모드는 실제 하드웨어를 건드리지 않고 이미 만들어진 명령어를 통해 (ex. system call) 운영체제에 요청을 보내는 것을 의미

유저 모드는 일반 응용 프로그램이 실행되는 제한된 모드이며,
직접 하드웨어에 접근할 수 없고 system call을 통해 운영체제에 기능을 요청한다.

3. 페이지 단위 메모리 관리 관점에서 lazy loading의 장점과 단점을 서술하시오.
```
가상주소를 통해 실제 물리프레임 주소에 접근을 할 때, 동적으로 물리 프레임을 할당하고 매핑을 만들어주기 때문에 시작하자마자 물리 메모리에 올리지 않아 부족한 공간의 활용도가 높다.
단점은 램이 실제로 꽉 찼을 때, 디스크에 swap in, out하는 트래픽이 많이 발생하므로 느려질 수가 있고 실제로 디스크 영역을 활용하기 때문에 디스크 용량이 많이 남아있지 않더라도 느려지는 단점이 존재한다.
```
```
Lazy Loading은 프로그램 시작 시 모든 페이지를 메모리에 올리지 않고,
실제로 접근되는 시점에 page fault를 통해 필요한 페이지를 로드하는 방식이다.

장점:
- 사용하지 않는 페이지를 미리 적재하지 않아 메모리 사용량을 줄일 수 있다.
- 프로그램 시작 속도가 빨라질 수 있다.

단점:
- 페이지에 처음 접근할 때 page fault와 디스크 I/O가 발생하여 지연(latency)이 생긴다.
- 메모리가 부족한 상황에서는 swap in/out이 빈번해져 성능이 저하될 수 있다.
```

4. 프로세스 A는 디스크에서 파일을 읽어 네트워크를 통해 외부로 전송하고자 한다. 이 과정에서 사용되는 시스템 콜을 기능별로 나누어 설명하시오. (Pintos에 Network 가 있다고 가정)
```
SYS_READ  : fd 파일 디스크립터가 0,1 이 아닐 경우 실제 파일에서 읽어오는 것이므로 먼저 파일을 읽는다.
SYS_WRITE : 읽은데이터를 fd가 1인 STD_SYSOUT 을 통해 데이터를 특정 네트워크 경로로 보낸
```
```
1. 파일 읽기
- process A는 open() 시스템 콜로 파일을 연다.
- 이후 read() 시스템 콜을 사용하여 디스크의 파일 데이터를 사용자 버퍼로 읽어온다.

2. 네트워크 전송
- socket() 시스템 콜로 소켓을 생성한다.
- connect()를 통해 외부 서버와 연결한다.
- write() 또는 send() 시스템 콜을 사용하여 읽어온 데이터를 네트워크로 전송한다.

즉,
디스크 → 사용자 버퍼 → 소켓 → 네트워크

```
Supplemental Page Table(SPT)은 각 프로세스의 가상 페이지에 대한 추가 정보를 관리하기 위해 사용된다.

하드웨어 페이지 테이블은 단순히 가상 주소와 물리 주소의 매핑 정보만 관리하지만,
SPT는 다음과 같은 추가 정보를 저장한다.

- 해당 페이지의 타입(anonymous/file-backed)
- 페이지의 writable 여부
- swap disk 위치
- lazy loading을 위한 파일 정보
- 현재 메모리에 적재되어 있는지 여부

이를 통해 page fault가 발생했을 때
운영체제가 어떤 방식으로 페이지를 복구(page in)해야 하는지 판단할 수 있다.
```
