    int *dp = (int *)malloc((n + 1) * sizeof(int));
    dp[1] = 1;
    dp[2] = 1;

    for (int i = 3; i <= n; i++) {

```
송신측 (클라이언트) - encapsulation
4계층에서 TCP헤더로 감싸 TCP 세그먼트를 만든다.
3계층에서 IP헤더로 감싸 IP 패킷을 만든다.
2계층에서 Ethernet 헤더와 Ethernet Trailer로 감싸 프레임을 만든다.

수신측 (서버) - decapsulation

3계층에서 IP헤더를 벗겨 가야 할 목적지 IP로 이동한다.
4계층에서 TCP헤더를 벗겨 데이터를 확인 후
서버 측에서 데이터를 확인 후 (SYN)
다시 이 과정을 한번 더 반복해 (SYN + ACK)를 서버측에서 전송후
클라이언트에서 마지막으로 (ACK)를 통해 전달이 잘 되었다는 신호를 통해 정상적인 통신이 이뤄진다.

```
1. 사용자가 브라우저 주소창에 https://www.google.com/search?q=정글 을 입력하고 엔터를 누른다.

2. 브라우저는 URL을 파싱하여
   - 프로토콜: https
   - 호스트명: www.google.com
   - 경로 및 쿼리: /search?q=정글
   로 구분한다.

3. 먼저 DNS 조회를 통해 www.google.com에 대응하는 IP 주소를 얻는다.
   (브라우저 캐시, 운영체제 캐시, DNS 서버 등을 순차적으로 확인할 수 있다.)

4. IP 주소를 얻으면 클라이언트는 서버의 443번 포트(HTTPS 기본 포트)로 TCP 연결을 시도한다.
   이때 3-way handshaking이 일어난다.
   - 클라이언트 → 서버: SYN
   - 서버 → 클라이언트: SYN+ACK
   - 클라이언트 → 서버: ACK

5. TCP 연결이 완료되면, HTTPS이므로 추가로 TLS 핸드셰이크를 수행한다.
   이 과정에서 서버 인증서 검증, 암호화 방식 협상, 세션 키 설정 등이 이루어진다.

6. 그 후 브라우저는 HTTP 요청 메시지를 만든다.
   예:
   GET /search?q=정글 HTTP/1.1
   Host: www.google.com
   ...

7. 이 요청 데이터는 송신 측에서 캡슐화된다.
   - 응용 계층: HTTP 요청 생성
   - 전송 계층: TCP 헤더를 붙여 세그먼트 생성
   - 네트워크 계층: IP 헤더를 붙여 패킷 생성
   - 데이터링크 계층: Ethernet 헤더/트레일러를 붙여 프레임 생성
   - 물리 계층: 비트 형태로 변환되어 네트워크를 통해 전송

8. 중간의 라우터들은 IP 헤더를 보고 목적지 방향으로 패킷을 전달한다.
   각 홉마다 프레임의 MAC 주소는 바뀔 수 있지만, IP의 출발지/목적지 주소는 기본적으로 유지된다.

9. 서버에 도착하면 역캡슐화가 일어난다.
   - 데이터링크 계층에서 목적지 MAC 확인 후 프레임 헤더/트레일러 제거
   - 네트워크 계층에서 목적지 IP 확인 후 IP 헤더 제거
   - 전송 계층에서 목적지 포트 확인 후 TCP 헤더 제거
   - 응용 계층의 웹 서버(예: Google 서버)가 HTTP 요청을 처리

10. 서버는 요청에 대한 HTTP 응답(HTML 등)을 만들어 다시 클라이언트로 전송한다.
    이 응답도 같은 방식으로 캡슐화되어 네트워크를 통해 전달된다.
