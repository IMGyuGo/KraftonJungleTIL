# 🧠 소프트웨어 개발 방식 변화 & 협업/회고 정리

## 1. 📉 기존 개발 방식 (Waterfall)의 한계

### 🔹 특징

* 기획 → 설계 → 개발 → QA → 배포 순차 진행
* 초기에 **3년 뒤 사용자 요구까지 예측**
* 문서 중심 협업

### 🔹 문제점

* ❗ 시장 변화 속도와 불일치 (모바일 시대 → 빠른 피드백 요구)
* ❗ 일정 지연 → QA/배포 시간 압축
* ❗ 책임 전가 구조 발생

  * 기획 ↔ 개발 ↔ QA ↔ 운영 서로 blame
* ❗ 문서 과도 → 협업 비효율
* ❗ QA/운영은 상대적으로 낮은 권한 (2~3등 시민)

---

## 2. ⚡ Agile 등장 배경

### 🔹 핵심 철학

* 문서보다 **커뮤니케이션**
* 말보다 **Working Software**
* 긴 개발보다 **빠른 반복 (Iteration)**

### 🔹 대표 방법론

* Agile
* XP (Extreme Programming)
* Scrum

---

## 3. 🧪 테스트 자동화 & TDD 흐름

### 🔹 기존 문제

* 사람이 직접 테스트 → 느림 / 오류 발생

### 🔹 해결 방향

* 테스트를 코드로 작성 (자동화)

### 🔹 변화

* 개발자가 테스트 코드 작성
* 테스트 없는 코드는 인정 안 됨
* 테스트 커버리지 중요

### 🔹 테스트 종류

* Low-level (Unit Test) → 개발자
* High-level (Functional Test) → QA

---

## 4. 🚀 DevOps & CI/CD 등장

### 🔹 문제

* 운영팀 = 배포 책임 → 매우 보수적
* 배포 주기 길어짐 (1~3개월)

### 🔹 해결

* 배포 자동화 (CI/CD)

### 🔹 특징

* 코드 → 테스트 → 배포 자동화
* 하루 수십~수백 번 배포 가능
* 롤백 전략 / 카나리 배포

### 🔹 DevOps 역할

* 개발 + 운영 + 자동화
* 회사마다 정의 다름

---

## 5. ☁️ 운영 환경 변화 (클라우드 시대)

### 🔹 과거

* 물리 서버 구매 → 설치 → 운영

### 🔹 현재

* 클라우드 (AWS 등)
* Infrastructure as Code

### 🔹 결과

* 운영도 개발 영역으로 확장
* DevOps/SRE 등장

---

## 6. 🔁 Postmortem (회고) 제대로 하는 방법

### ❌ 잘못된 방식

* 사람 blame
* “누가 잘못했는지” 찾기
* 감정적인 피드백

---

### ✅ 올바른 방식

#### 1. What went well (잘한 점)

* 다음에도 반복할 행동 정의

#### 2. What to improve (개선할 점)

* ❗ “What’s wrong” ❌
* ✅ “What’s next” 중심

---

## 7. 🎯 SMART 원칙 (회고 액션 기준)

| 항목 | 의미                      |
| -- | ----------------------- |
| S  | Specific (구체적)          |
| M  | Measurable (측정 가능)      |
| A  | Achievable (달성 가능)      |
| R  | Result-oriented (결과 중심) |
| T  | Time-bound (기간 명확)      |

👉 핵심: **1주 내 실행 가능한 것만**

---

## 8. 🧩 회고 진행 방법 (실전 프로세스)

### 1️⃣ 포스트잇 작성

* 잘한 점 / 개선점 자유롭게 작성
* ❗ 절대 의견 비판 금지

### 2️⃣ 공유

* 작성자가 직접 설명

### 3️⃣ 그룹핑

* 퍼실리테이터가 유사 항목 묶기

### 4️⃣ 개선안 도출

* SMART 기준 적용

---

## 9. ⚠️ 협업 핵심 원칙

### ❗ 절대 금지

* 개인 비난 (Blame)
* 공개적인 지적

### ✅ 권장

* 문제를 **사람이 아닌 시스템 관점으로**
* 객관화된 데이터 기반 논의

---

## 10. 💡 핵심 한 줄 정리

> 🔥 “사람을 바꾸려 하지 말고, 프로세스를 개선하라”

---

## 11. 📊 전체 흐름 요약

```
Waterfall (느림, 문서 중심)
    ↓
Agile (빠른 반복, 협업 중심)
    ↓
Test Automation (TDD)
    ↓
CI/CD (배포 자동화)
    ↓
DevOps / 클라우드
    ↓
지속적 개선 (Postmortem)
```
