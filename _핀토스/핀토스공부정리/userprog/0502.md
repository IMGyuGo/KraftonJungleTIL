# 배경
```
지난 과제의 테스트 코드도 커널의 일부로 실행 -> 시스템의 특권 영역에 완전히 접근
OS위에서 usrprog 실해하기 시작하면 더 이상 그렇지 않음

Pintos는 동시에 둘 이상의 프로세스를 실행
각 프로세스는 하나의 스레드를 가짐 - 다중 스레드 프로세스는 지원하지 않음
사용자 프로그램은 혼자 전체 머신을 차지하고 있다고 믿음
여러 프로세스를 동시에 로드하고 실행 시, 환상을 유지하려면 메모리, 스케줄링, 그 밖의 상태를 올바르게 관리 해야 함.

테스트 코드를 커널에 직접 컴파일 했기 때문에, 커널 내부의 특정 함수 인터페이스를 요구할 수 밖에 없었음
사용자 프로그램을 실행해 운영체제 테스트
```

# 가상 주소
```
63..48   47..39   38..30   29..21   20..12   11..0
Sign     PML4     PDPT     PD       PT       Offset
Extend   index    index    index    index    page offset
16bit    9bit     9bit     9bit     9bit     12bit

가상 주소 = "어느 페이지인가" + "그 페이지 안에서 몇 번째 바이트인가"
offset : 뒤쪽 12비트
Pintos 기준 페이지 크기가 PGSIZE = 4096 byte = 2^12 (페이지 안의 바이트 위치를 표현하기 위함)
```

```
CR3 레지스터
  -> PML4 테이블

가상 주소의 PML4 index 9비트
  -> PML4 엔트리 선택

PDPT index 9비트
  -> Page Directory Pointer Table 엔트리 선택

PD index 9비트
  -> Page Directory 엔트리 선택

PT index 9비트
  -> Page Table Entry 선택

PTE가 알려주는 물리 프레임 주소
  + offset 12비트
  = 최종 물리 주소
```
