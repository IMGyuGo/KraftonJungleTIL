# 핀토스 구현중 궁금증

## timer_interrupt()가 10ms 마다 한번 씩 발생 - 원천지가 어디일까?

```c
// init.c -> main() -> timer_init()
void timer_init(void)
{
    list_init(&sleep_list);

	uint16_t count = (1193180 + TIMER_FREQ / 2) / TIMER_FREQ;
	outb(0x43, 0x34);
	outb(0x40, count & 0xff);
	outb(0x40, count >> 8);

	intr_register_ext(0x20, timer_interrupt, "8254 Timer");
}
```

---

### 1. count 부터 outb까지

`타이머 인터럽트를 "발생시키기 전" 하드웨어 타이머 칩을 세팅하는 코드`

#### 8254 타이머

```
PC에 실제로 존재하는 하드웨어 칩
일정 주기로 인터럽트 신호를 발생시키는 장치
8254 타이머는 기본 입력 클럭이 1,193,180Hz
```

#### count

> Pintos는 "1초에 TIMER_FREQ번 인터럽트가 발생 하는 것을 원함". 예를 들어 TIMER_FREQ = 100이면 1초에 100번, 즉 10ms 마다 1번 타이머 인터럽트 발생

> count = 1193180 / 100 ≒ 11932  
> 딱 타이머가 11932번 클럭을 센 뒤 인터럽트를 한 번 발생시키게 하기위한 계산

#### outb

> 8254 타이머에게 어떤 방식으로 동작할지 명령하는 부분  
> outb(0x43, 0x34)
>
> > 0x43 포트 = PIT 제어 포트  
> > 0x34 = 현재 몇 번의 클럭인지 알려주는 값

#### 1. 8254 타이머란?

```
PC에 실제로 존재하는 하드웨어 타이머 칩
일정 주기로 인터럽트 신호를 발생시키는 장치
```

#### 2.

### 1. 코드가 하는 일

👉 **타이머 하드웨어가 주기적으로 신호를 발생시키고,
OS가 그 신호를 받아서 `timer_interrupt()`를 실행한다**

---

### 2. 흐름 전체 구조

```
[8254 타이머 하드웨어]
        ↓ (주기적으로 신호 발생)
[인터럽트 라인 (IRQ0)]
        ↓
[CPU 인터럽트 처리]
        ↓
[IDT (인터럽트 테이블)]
        ↓
[timer_interrupt()]
```

---

# 🔧 3. outb를 하는 이유 (핵심 포인트)

## 👉 결론 먼저

👉 **타이머 칩(8254)에 “몇 ms마다 인터럽트 발생시켜라” 설정하는 것**

---

## 🔍 조금 더 깊게

### 📌 8254 타이머란?

- PC에 실제로 존재하는 **하드웨어 타이머 칩**
- 일정 주기로 **인터럽트 신호를 발생시키는 장치**

---

### 📌 왜 outb를 쓰냐?

👉 CPU가 하드웨어 설정할 때 쓰는 방식이 **I/O 포트 통신**

```
outb(port, value)
```

- port: 하드웨어 주소
- value: 설정 값

---

### 📌 이 코드가 하는 일

```c
outb(0x43, 0x34);
outb(0x40, count & 0xff);
outb(0x40, count >> 8);
```

👉 의미:

1. **타이머 동작 모드 설정**
2. **몇 클럭마다 인터럽트 발생할지 설정**

---

### 📌 핵심 이해

👉 결국 이건:

```
"야 타이머야, 10ms마다 인터럽트 발생시켜"
```

라고 하드웨어에게 명령하는 것

---

# ⚡ 4. intr_register_ext의 역할

## 👉 결론

👉 **“인터럽트가 발생했을 때 어떤 함수 실행할지 등록하는 것”**

---

## 🔍 내부 개념 흐름 (코드 없이 설명)

### 1️⃣ 인터럽트 번호 기반 등록

```
0x20 → 타이머 인터럽트 번호
```

👉 OS는 이렇게 매핑함:

```
인터럽트 번호 → 실행할 함수
```

---

### 2️⃣ 내부적으로 하는 일

👉 크게 3단계

---

### (1) 인터럽트 핸들러 테이블에 저장

```
[인터럽트 번호 0x20] → timer_interrupt
```

---

### (2) IDT (Interrupt Descriptor Table) 설정

👉 CPU가 인터럽트 발생 시 참조하는 테이블

```
CPU: "0x20 인터럽트 발생했네?"
→ IDT 확인
→ 등록된 핸들러 실행
```

---

### (3) 인터럽트 활성화 준비

- 외부 인터럽트로 등록됨
- CPU가 받을 수 있는 상태로 설정

---

## 📌 핵심 한 줄

👉 `intr_register_ext`는

```
"이 인터럽트 들어오면 이 함수 실행해"
```

를 OS에 등록하는 것

---

# 🔁 5. 실제 동작 흐름 (완전체)

## 💥 실행 흐름

```
1. timer_init()
   ↓
2. outb → 하드웨어 타이머 설정
   ↓
3. intr_register_ext → 핸들러 등록
   ↓
4. 하드웨어가 주기적으로 인터럽트 발생
   ↓
5. CPU가 인터럽트 감지
   ↓
6. IDT 참고
   ↓
7. timer_interrupt() 실행
```

---

# 🧠 6. 중요한 직관

👉 timer_interrupt는 **스스로 도는 함수가 아님**

👉 **하드웨어가 강제로 실행시키는 함수**

---

# 🆚 7. 실제 OS와 비교

## ✅ Pintos

- 8254 직접 설정
- outb로 하드웨어 직접 제어
- 인터럽트 직접 등록
- 매우 low-level

---

## ✅ 실제 OS (Linux 등)

👉 구조는 같지만 훨씬 추상화됨

---

### 📌 공통점

- 하드웨어 타이머 존재
- 주기적 인터럽트 발생
- 인터럽트 핸들러 등록

---

### 📌 차이점

| Pintos             | 실제 OS                |
| ------------------ | ---------------------- |
| 8254 직접 사용     | APIC / HPET 등 사용    |
| outb 직접 사용     | 드라이버/커널 API 사용 |
| 단순 인터럽트 처리 | 복잡한 인터럽트 계층   |
| 단일 CPU 가정      | 멀티코어 지원          |

---

### 📌 실제 OS 추가 개념

- Local APIC Timer
- High Precision Timer (HPET)
- Tickless kernel (인터럽트 최소화)

---

## 🔥 핵심 비교 한 줄

👉 Pintos는:

> “하드웨어를 직접 만지는 교육용 OS”

👉 실제 OS는:

> “하드웨어 위에 추상화 레이어를 둔 산업용 OS”

---

# 🎯 발표용 마무리 한 문장

👉 이렇게 말하면 깔끔하다:

> “Pintos에서 timer_interrupt는 코드가 반복 실행되는 구조가 아니라,
> 하드웨어 타이머가 주기적으로 인터럽트를 발생시키고,
> OS가 그 인터럽트를 특정 함수에 매핑해서 실행시키는 구조입니다.”

---

원하면 다음 단계로
👉 **timer_interrupt → thread_tick → 스케줄링까지 연결 흐름**
(진짜 핵심 Pintos 포인트)도 이어서 정리해줄게.
