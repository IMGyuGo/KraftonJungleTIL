## 핵심 개념

1. Interrupt 개념

   ```
   인터럽트 ON → “손 펼친 상태 (이벤트 받음)”
   인터럽트 OFF → “주먹 쥔 상태 (아무것도 못 받음)”

   인터럽트 끄면:
   ⛔ timer interrupt 안 발생
   ⛔ tick 증가 안 함 (시간 멈춤)
   ⛔ thread_tick 실행 안 됨
   ⛔ 스케줄링 멈춤 (CPU 독점 상태)
   ⛔ 키보드/마우스 입력 무시

   “시스템이 멈춘 것처럼 보임”
   ```

2. Interrupt 오래 끄면 왜 문제?

   ```
    단순히 tick overflow 문제가 아님
    진짜 문제:
        스레드 실행 기회 없음
        시스템 반응 없음 (벽돌 상태)

    중요한 포인트
        입력이 없으면 문제 없어 보일 수도 있음
        하지만:
        “시스템이 일을 못하는 상태 자체가 문제”
   ```

3. Interrupt 다시 켜면?

   ```
    쌓인 이벤트 → 한 번에 처리될 수도 있음
    하지만:
    지연 발생
    burst 처리

    - Pintos 원칙:

    Interrupt disable 구간은 최소화해야 함
   ```

4. 구조적 이해 비유
   ```
   sleep list / ready list → malloc의 free list와 유사
   인터럽트 → 이벤트를 받는 “입구”
   interrupt off → “문 닫힘 상태”
   ```
