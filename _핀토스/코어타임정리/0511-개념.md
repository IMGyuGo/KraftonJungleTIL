이번 코어타임의 핵심은 크게 5가지였습니다.

1. **MMU와 페이지 테이블 흐름**
2. **Page Fault 처리 흐름**

# 1. MMU와 페이지 테이블 흐름

유저 프로그램이 실행되면:

```text
CPU
 → User Virtual Address 접근
 → MMU가 주소 변환
 → 현재 프로세스의 PML4 기준으로 페이지 테이블 탐색
```

핵심:

* MMU는 CPU 내부에서 주소 변환 담당
* CR3 레지스터가 현재 프로세스의 PML4 주소를 들고 있음
* Virtual Address를 Physical Address로 변환

---

## 페이지 테이블 탐색 구조

x86-64 기준:

```text
PML4
 → PDPT
   → PD
     → PT
       → Physical Frame
```

각 단계에서:

```text
Present Bit == 1 ?
```

확인 후 다음 단계 이동.

---

## 가상 주소 분해

48bit VA:

```text
9bit | 9bit | 9bit | 9bit | 12bit
 PML4  PDPT   PD     PT    OFFSET
```

예시:

```text
0x401234
```

를:

```text
PML4 index
PDPT index
PD index
PT index
OFFSET
```

로 잘라 탐색.

---

## 중요한 개념

### Mapping이 있다는 의미

```text
Virtual Page
 ↔ Physical Frame
```

연결이 존재한다는 뜻.

즉:

```text
가상 주소 → 실제 RAM 위치
```

를 찾을 수 있다는 의미.

---

# 2. Page Fault 처리 흐름

핵심 흐름:

```text
유저 VA 접근
 → Mapping 없음 OR 권한 위반
 → Page Fault 발생
 → 커널 진입
 → page_fault() 호출
```

---

## page_fault()에서 확인하는 것

### CR2

```text
Fault 발생한 Virtual Address
```

읽기.

---

## fault 정보 확인

```text
not_present ?
write access ?
user mode access ?
```

확인.

---

# 3. VM에서 처리 가능한 Fault인지 판단

## 처리 불가능

예시:

```text
Read-only page에 write 시도
Kernel Address 접근
```

→ 즉시 종료

```text
exit(-1)
```

---

## 처리 가능한 경우

조건:

```text
User Virtual Address
AND
not-present fault
```

이면:

```text
vm_try_handle_fault()
```

호출.

---

# 4. vm_try_handle_fault() 핵심 흐름

## (1) Page Boundary 내리기

예시:

```text
fault addr = 0x401233
```

↓

```text
0x401000
```

로 변환.

이유:

* 페이지 단위(4KB)로 관리하기 때문

---

## (2) SPT에서 페이지 찾기

```c
spt_find_page()
```

호출.

의미:

```text
이 VA가 정상적인 페이지인가?
```

검사.

---

## (3) 페이지가 존재하는 경우

### write 접근이면:

```text
writable 확인
```

필요.

---

## (4) 실제 Frame에 올리기

```c
vm_do_claim_page()
```

호출.

핵심 역할:

```text
page ↔ frame 연결
PML4 mapping 등록
swap/file에서 데이터 로딩
```

# 5. struct page vs Page VA 차이

코어타임에서 많이 헷갈린 부분.

---

## Page VA

```text
0x401000
```

같은 "주소".

---

## struct page

페이지 메타데이터.

예시:

```c
struct page {
    void *va;
    struct frame *frame;
    bool writable;
    ...
};
```

즉:

```text
"이 페이지를 어떻게 관리할 것인가?"
```

에 대한 정보.

# 7. Swap / Eviction / LRU

---

## Swap이란?

RAM 부족 시:

```text
덜 사용하는 페이지를 디스크로 내보냄
```

---

## Eviction

희생 페이지 선정 과정.

즉:

```text
"누굴 RAM에서 뺄 것인가?"
```

---

## LRU 근사 알고리즘

실제 Linux/Pintos는:

```text
Accessed Bit
```

활용.

예시:

```text
1 → 최근 사용
0 → 오래 사용 안 함
```

---

## Clock Algorithm

흐름:

```text
1이면:
 → 0으로 바꾸고 넘어감

0이면:
 → 희생자 선정
```

---

# 8. Page In/Out vs Swap In/Out

코어타임에서 중요하게 나온 부분.

---

## Swap In/Out

무조건:

```text
Swap Disk
```

사용.

---

## Page In/Out

더 넓은 개념.

예:

* File-backed page
* mmap
* executable
* swap

전부 포함 가능.

즉:

```text
Swap In/Out ⊂ Page In/Out
```

---

# 9. Dirty Bit 개념

핵심:

```text
메모리에서 수정되었는가?
```

---

## Dirty == 0

원본 파일과 동일.

→ 그냥 버려도 됨.

---

## Dirty == 1

메모리에서 수정됨.

→ backing store/file에 저장 필요.

---

# 10. 왜 Virtual Memory를 사용하는가

핵심 이유로 나온 것:

---

## 보안

물리 메모리 직접 접근 허용 시:

```text
유저 프로그램이 커널 메모리 공격 가능
```

MMU + 페이지 테이블을 통해:

```text
권한 검사
주소 분리
보호
```

가능.

---

## 추가 장점

* 연속된 가상 주소 제공
* 실제 RAM은 조각나 있어도 됨
* 외부 단편화 감소
* 프로세스 격리
