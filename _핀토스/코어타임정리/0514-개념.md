## 0514 개념 코어타임 요약

* 공부 방법 관련

  * 함수 안에서 호출되는 함수들을 계속 따라 들어가며 흐름을 추적하는 방식으로 공부 방향을 잡음
  * “왜 이 함수가 필요한가?”를 기준으로 흐름 이해 시작 

---

## 핵심 개념 정리

### 1. `vm_alloc_page_with_initializer`

* 역할:

  * 페이지를 생성하면서 초기화 정보를 등록하는 함수
* 하지만:

  * 페이지 생성 시 바로 frame을 붙이지 않음
* 이유:

  * Lazy Loading 때문
  * 실제로 사용되지 않는 함수/페이지까지 RAM에 올리면 메모리 낭비 발생 

---

### 2. Lazy Loading 흐름

* 처음에는:

  * SPT에만 등록
  * frame은 없음
* 실제 접근(page fault 발생) 시:

  * frame 할당
  * 실제 데이터 로드
* 결과:

  * 사용하지 않는 페이지는 끝까지 메모리에 안 올라감 

---

### 3. SPT 등록 의미

* “SPT 등록” = `struct page` 생성 및 초기화
* 내부에는:

  * va
  * writable
  * hash_elem
  * union(uninit/anon/file page)
    등이 들어감 

---

### 4. `uninit page`

* 페이지 최초 생성 상태
* 특징:

  * frame 없음
  * 아직 anon/file 타입 확정 전
* 내부 정보:

  * initializer
  * aux
  * vm_type
* 이후 실제 접근 시 anon/file page로 변환됨 

---

### 5. union 구조 이해

* `union` 안에는:

  * uninit_page
  * anon_page
  * file_page
* 하지만 동시에 하나만 사용
* 현재 페이지 상태에 맞는 구조체만 활성화됨 

---

### 6. 왜 처음엔 `VM_UNINIT` 인가?

* 처음엔 실제 타입을 아직 모름
* 일단 uninit 상태로 생성
* 이후 page fault → lazy load 과정에서:

  * anon/page file로 변환됨
* mmap 구현 시에는 `VM_FILE` 사용 

---

### 7. `initializer` 함수 포인터

* initializer는 함수 포인터
* 대표적으로:

  * `anon_initializer`
  * `file_backed_initializer`
* 역할:

  * 실제 페이지 타입별 초기화 수행 

---

### 8. Page Fault 흐름

흐름 정리:

```text
유저 프로그램 실행
→ 아직 frame 없는 주소 접근
→ page fault 발생
→ vm_try_handle_fault
→ lazy_load_segment
→ frame 할당
→ 실제 데이터 로드
```



---

### 9. `load_segment`

* 기존 eager loading:

  * 파일 내용을 즉시 전부 메모리에 올림
* 현재 구현할 lazy loading:

  * 초기화 정보만 저장
  * 실제 접근 시 로드 

---

### 10. `pg_round_down` 중요한 이유

예시:

```text
0x8048123
↓
pg_round_down
0x8048000
```

* 같은 페이지의 시작 주소를 얻기 위해 사용
* `pg_round_up` 사용 시:

  * 다음 페이지로 넘어가버릴 수 있음
